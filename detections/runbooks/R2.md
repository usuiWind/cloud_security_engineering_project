# R2: the model key read by anyone but the gateway

**Rule:** `detections/R2-model-key-read.kql`, Sentinel, every 5 min over 1 h. Fires on `GetSecretValue` for `meridian/gemini-api-key` (or any denied `GetSecretValue`) where the principal is not `meridian-ai-gateway`. Suppressed for 1 h after it fires.

## What it means
Something other than the gateway tried to read the Gemini API key. The secret's resource policy denies everyone but the gateway role, so a read normally fails; the attempt itself is the signal. A *successful* read by anyone else would mean the policy was changed.

## First checks
1. Whose ARN (`UserIdentityArn`)?
2. Was the read denied (`ErrorCode` = `AccessDenied`)? A success is an emergency.
3. The source IP (`SourceIpAddress`). Is it yours?
4. Has the secret's resource policy or the secrets key policy changed recently (`PutResourcePolicy`, `PutKeyPolicy` in `AWSCloudTrail`)?

## Containment if a read ever succeeds
1. Delete the key in Google AI Studio and create a new one.
2. Store the new key as in runbook 3.5b, then force a gateway cold start (`aws lambda update-function-configuration --function-name meridian-ai-gateway --description "key rotated"`).
3. Review the secret's resource policy and the principal's other activity.

## False positives
A rename of the gateway role, so its ARN no longer contains `meridian-ai-gateway`. Update the rule when the role is renamed. An engineer proving the denial for evidence (3.5b) also fires it.
